There is no single required way to use HyperFrames. Start from what you already have and what you are trying to accomplish.

| You have | Start here | Why |
| --- | --- | --- |
| You want to explore without local setup | [Browser Playground](https://www.hyperframes.dev/) | Open and remix public HyperFrames work in the browser. |
| You want to create inside a supported AI chat | [HyperFrames MCP](/guides/mcp) | Use a hosted connector and cloud rendering without the local CLI. |
| An idea, URL, script, PR, song, or video file | [Create with an agent](/guides/create-with-agent) | The agent can choose the right workflow and build the first version. |
| A HyperFrames project you want to review or edit | [Studio](/studio) | Studio is the visual workspace for timing, design, animation, and export. |
| A specific effect or scene you want to reuse | [Catalog](/catalog) | Browse ready-made blocks and components instead of rebuilding them. |
| An application or automation you want to integrate | [Developers](/developers) | Use the CLI, SDK, player, packages, schemas, and deployment tools. |

## Agent or Studio?

Most projects use both.

Use the **agent** when the change needs planning, new scenes, new media, source-code work, or coordination across the project.

Use **Studio** when you can point at what you want to change: move an element, edit text, trim timing, adjust a keyframe, change a style, or export a version.

<Tip>
  A useful rule: if you can fix it by selecting something visible, try Studio. If you need to explain a broader outcome, ask the agent.
</Tip>

## Catalog or custom work?

Use the Catalog when a reusable visual already matches the job: a lower third, transition, chart, caption style, social card, or code animation.

Ask the agent for custom work when the visual needs to carry your particular story, product interface, brand system, or data.

## Human guide or developer reference?

The **Guides** and **Studio** sections explain what to do and what you should see.

The **Developers** section explains commands, APIs, packages, schemas, deployment, and implementation details. You should not need it for normal review and editing.
